Risque Brettanomyces

Un simulateur Power BI pour les vins de la vallée du Rhône, sur des données fictives. On saisit l'analyse d'un lot et le rapport estime le risque que la levure se développe, puis indique la correction à faire en cave.

Objectif

Agir avant que le vin ne soit marqué

Brettanomyces est une levure qui donne au vin des odeurs animales, de cuir ou d'écurie. Une fois qu'elle s'est développée, on ne peut plus revenir en arrière. Le maître de chai a donc besoin de savoir, lot par lot, si le risque est réel et ce qu'il peut corriger tout de suite, en général le SO₂ libre.

On saisit l'analyse du lot à gauche. La jauge donne la probabilité que la population augmente au prochain contrôle, en vert sous 30 %, en orange jusqu'à 60 % et en rouge au-delà. À droite, le SO₂ actif est comparé au seuil de protection de 0,5 mg/L, puis le rapport indique le SO₂ libre à viser à ce pH.

Les données

120 lots fictifs

Les lots et les huit domaines sont inventés, générés en Python. Les valeurs restent proches de ce qu'on mesure vraiment dans un chai, et le lien entre l'analyse et l'évolution de la levure suit ce que décrit la littérature œnologique.

VariableCe qu'elle mesure
pHL'acidité du vin. Plus il est haut, moins le SO₂ protège
SO₂ moléculaireLa part active du SO₂, calculée à partir du SO₂ libre et du pH
Température de caveLa levure se développe plus vite au chaud

Le modèle

Une régression logistique en Python

Le modèle apprend, sur les 120 lots, quelles analyses précèdent une hausse de la population. Ses coefficients sont exportés dans une table que Power BI lit. Le calcul du risque se fait ensuite en DAX, ce qui permet au simulateur de répondre dès qu'on change une valeur.

Validation croisée 5 × 20Valeur
AUC0,83
Bonnes prédictions76 %
Part de lots qui évoluent41 %

Le pH et le SO₂ moléculaire sont les deux variables qui pèsent vraiment. Avec seulement 120 lots, les autres effets restent incertains, et un vrai suivi de cave demanderait plus de lots avant de s'y fier.

Les mesures DAX

Elles sont rangées dans une table _Mesures. Voici celles qui font tourner le simulateur.

SO2 moleculaire simule

La part active du SO₂ libre. Elle baisse vite quand le pH monte, c'est pour ça qu'un même dosage protège moins un vin peu acide.

DIVIDE ( [SO2 libre choisi], 1 + POWER ( 10, [pH choisi] - 1.81 ) )

Risque simule

La formule de la régression logistique, réécrite en DAX. Elle va chercher chaque coefficient dans la table exportée par Python, puis applique la fonction logistique.

VAR b0  = LOOKUPVALUE ( coefficient[Coefficient], coefficient[Variable], "Constante" )
VAR bPH = LOOKUPVALUE ( coefficient[Coefficient], coefficient[Variable], "pH" )
-- même chose pour les cinq autres variables
VAR z = b0 + bPH * [pH choisi] + bSO * [SO2 moleculaire simule]
    + bT * [Temperature choisie] + bS * [Sucres choisis]
    + bB * [Barrique choisie] + bL * [Population choisie]
RETURN DIVIDE ( 1, 1 + EXP ( -z ) )

Niveau simule

Le risque traduit en trois niveaux, qui donnent aussi la couleur de la jauge.

SWITCH ( TRUE (),
    [Risque simule] >= 0.6, "Élevé",
    [Risque simule] >= 0.3, "Modéré",
    "Faible" )

SO2 libre conseille

Le SO₂ libre qu'il faut atteindre pour avoir 0,5 mg/L de SO₂ actif au pH du lot.

0.5 * ( 1 + POWER ( 10, [pH choisi] - 1.81 ) )

pH choisi

La valeur saisie dans le bulletin. Les autres variables suivent le même principe, avec une valeur par défaut si rien n'est choisi.

SELECTEDVALUE ( 'Sim pH'[Sim pH], 3.65 )
